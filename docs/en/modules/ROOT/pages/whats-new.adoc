= What's new
:description: Everything that changed in this component since the {release-version} release.

[.lead]
New in the `{project-version}` development line — everything listed here landed **after the {release-version} release** and is not part of it. Every entry links to the section that documents it, and those sections carry the [.tag-new]#NEW# badge. Each brick of the suite keeps its own page of this kind; xref:home::whats-new.adoc[the ecosystem index] gathers them. When the next release train ships, this page is frozen with it and restarts empty on the dev line.

* **Jakarta WebSocket 2.2, lot 1** — the programmatic server API in the new optional `foy-websocket` module: `ServerContainer.addEndpoint(ServerEndpointConfig)`, the RFC 6455 handshake, a same-origin policy with the `io.vidocq.foy.websocket.allowed-origins` init parameter, sessions with limits, timeouts and close codes. Annotated endpoints and the client API come in later lots. xref:usage.adoc#websocket[Usage], xref:reference.adoc#websocket-module[reference].
* **WebSocket origin messages name the configured setting** — the init parameter `io.vidocq.foy.websocket.allowed-origins.setting-name` lets a runtime that fills the origins from its own key (Vidocq: `vidocq.websocket.allowed-origins`) have the refusal WARNING and the malformed-entry error name that key. xref:usage.adoc#websocket-origins[Usage], xref:reference.adoc#websocket-module[reference].
* **Takeover SPI** — `io.vidocq.foy.spi.websocket` (`WebSocketUpgradeHandler`, `WebSocketListener`, `WebSocketPeer`) and the `ComponentInstantiator` context attribute let a WebSocket implementation run on Foy without reaching into `foy-core`. xref:reference.adoc#websocket-spi[Reference].
* **`FoyChappeBoot.Builder.initParameter`** — sets a servlet-context init parameter from code. xref:reference.adoc#foychappeboot[Reference].
* **Fix: dynamic filter mappings honour `isMatchAfter`** (BUG-20261114-01). xref:migration.adoc[Behaviour changes].
* **Undeploy in order** (BUG-20261114-08, BUG-20261115-01 to -06) — closing a deployment refuses new requests and WebSocket handshakes with `503 Service Unavailable` and `Retry-After: 3` (the undeploy's bound, in seconds), never with an error page of the application; it closes the upgraded connections (a WebSocket peer gets its 1001 Close), lets the requests in service finish for up to 2 s, refuses cross-context dispatches into the application, then destroys it. Close the deployment before you stop the server. xref:migration.adoc[Behaviour changes], xref:reference.adoc#foychappeboot[`Mounted.close()`].

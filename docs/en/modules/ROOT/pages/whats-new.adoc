[.lead]

== CDI

* **The request context is active for each request** — when `FoyChappeBoot` is given a `BeanManager`, Foy activates the CDI request context around each request, through the standard `RequestContextController`, so `@RequestScoped` beans work in servlets, filters and listeners, and the container fires the request context events. {release-version} activated it under no container: a `@RequestScoped` bean failed with `ContextNotActiveException` (BUG-20261010-01). This needs a container that provides `RequestContextController`, as Weld does; Vauban 0.4 provides none, so under Vauban the request context is still not active. The session context followed (next entry). xref:reference.adoc#other-containers[Other CDI containers].
* **The session context for `@SessionScoped` beans** — Foy now provides its own context for `@SessionScoped` (foy#21): one instance per HTTP session, the old instances kept until the end of a request that calls `invalidate()`, destruction on expiry and undeploy, and the `@Initialized` / `@BeforeDestroyed` / `@Destroyed(SessionScoped.class)` events. Registered by a portable extension on Weld and other CDI Full containers, and by `foy-cdi-vauban` on Vauban — except in an application whose every bean archive was processed by `vauban-processor` at build time, where Vauban drops the context (BUG-20261010-08, a Vauban issue). {release-version} had no session context at all: a `@SessionScoped` bean failed with `ContextNotActiveException`. Request listener order and failure handling changed with it (xref:migration.adoc#cdi-contexts[Migration]). xref:reference.adoc#other-containers[Other CDI containers].
* **Proven on Weld SE** — the new `foy-it-weld` module, never published, runs Foy on Chappe with Weld SE 6.0 without `foy-cdi-vauban`: servlets, filters and listeners get injection, request-scoped beans live per request, session-scoped beans per HTTP session (foy#18, foy#21). xref:reference.adoc#other-containers[Other CDI containers].
